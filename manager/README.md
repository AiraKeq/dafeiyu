# 大肥鱼聊天管理器

一处查看运行、性格、成长与记忆。沿用现有云端 AstrBot + NapCat + whale_memory，不安装另一套机器人，不迁移记忆，不改既有人设或插件。

## 打开

双击桌面的 [大肥鱼聊天管理器](<C:/Users/ASUS/Desktop/大肥鱼聊天管理器.lnk>)，它指向用户私有目录中的 [安装版入口](<C:/Users/ASUS/.ssh/whale-manager-app/大肥鱼聊天管理器.cmd>)。F盘保留开发源码与开发启动脚本；日常使用桌面安装版，避免运行可能被其他账户改写的工作区源码。

启动器会启动或复用 **本机管理器**，打开 `http://127.0.0.1:17865/`，用两分钟有效的一次性登录链接换取本机会话。链接令牌随即从地址栏清除。会话有效期12小时，浏览器授权只保存在当前页面内存；过期、关闭页面或刷新整个网页后，再次双击入口即可重新授权。页面内的“刷新状态”按钮不需要重新登录，也不丢弃编辑草稿。直接手打地址时只展示登录说明，单独的Cookie不能换取管理权限。

**打开管理器不等于启用QQ聊天。** 关闭网页、本机管理器或电脑，也不等于停止云端聊天；要停止QQ回复，请在总览点击“停止服务”。

本机需要已安装的 Node.js 24 与 Windows OpenSSH、原有SSH密钥及已确认的服务器指纹。不要求重新输入模型Key或管理密码，不复制密钥，不新增公网端口。

F盘源文件不直接服务日常页面。后续修改源码后，需要明确同步安装版；不要只刷新浏览器就认为安装版已经更新。远端管理接口也改变时，应先核验部署版本与内容摘要一致。维护管理器不需要启动/重装QQ机器人。

## 可以做什么

- **总览**：AstrBot真实运行态、QQ连接状态、版本、模型名称与密钥是否已配置、对话空间、待回复数、日评完成日期、分页状态和关键规则。模型可用性不主动探测，不消耗模型用量。
- **启用 / 停止**：弹窗明确确认后，控制已经核验的那个AstrBot容器。不会启动或重启NapCat，不拉镜像，不重建容器。启动失败与连接丢失会区分“已停止”和“结果未知”。
- **性格与成长**：修改基础性格、各对话空间的当前成长便笺。保留按真实交流逐渐成长的机制；不存在的成长历史不虚构为时间线。显示实际字符数和2000字符轻量润色预算。
- **记忆档案**：按对话空间分别浏览、搜索事件和聊天原文；显示事件I重要度、随时间计算的R新近度与日评恢复后的预计处理。可以修改单个事件，或输入确认词删除单个事件。原文只读。
- **备份与规则**：创建冷态记忆备份，查看管理器自己的备份记录，查看关键规则。规则只读，不偷偷改变冷却、分页、识图、身份或权限。

## 必须知道的边界

**编辑和备份前，先停止AstrBot。** 页面与服务端都会检查；保存不会自动重启。写入先建备份，再比较版本，防止覆盖另一个窗口的修改。数据/版本变化会拒绝旧请求，需要刷新后重新确认。

**启用可能立即处理暂停前的队列，并恢复积压日评。** 日评会按原规则压缩、归档或删除到期数据，不保证等新消息才说话。启用按钮的确认框会提醒这点。服务进程正在运行不等于QQ在线，也不等于模型API可用。

**删除一条事件不等于彻底遗忘。** 原始消息、成长便笺、原生AstrBot历史、队列、分页、图片缓存及旧备份不会随之清除。这里不提供跨系统清空、原文编辑、队列重写或手动日评，以免重发或误删。

R值随时间衰减，即使暂停也会变化；查看页面不会执行生命周期清理。“存储状态”和“恢复整理后的预计处理”是两个不同概念。所有页面时间按本机浏览器时区显示；机器人回复/日评规则按北京时间。

2000字符预算只针对已有轻量润色的人设输入。它不同于主聊天/每日整理的预算，也不包含浏览器显示的所有成长便笺；超限会提示，不擅自截短已保存的人设。

## 备份与故障处理

云端管理器备份位置：`/opt/qq-deepseek/backups/whale-manager/snapshots/<backup_id>/`。

每个完整备份包含：
- `memory.sqlite3`：所有scope的消息、事件、成长便笺及原数据库表；复制WAL并仅在私有暂存中整合，校验完整性。
- `personality.json`：仅基础性格，不包含模型Key或核心全配置。
- `manifest.json`：备份ID、操作与时间、文件SHA-256。

性格修改前还会把旧插件配置私下保留到 `private-config/`；不通过页面开放这些配置或聊天正文下载。备份会占用云端磁盘，当前不会自动删旧备份。

恢复属于维护操作，**没有一键恢复/撤销按钮**。需要恢复时保持暂停，记录备份ID，要求维护者校验清单、当前库、WAL与版本，并先保留当前数据再恢复；不要在运行中直接覆盖SQLite。备份恢复不能保证已发送QQ消息“恰好一次”。

如提示“上次操作未确认完成”，不要反复点击保存/启用。服务端保留未完成意图供人工核验；紧急停止仍可在容器身份可信时使用。网络超时后的实际状态可能未知，重新读取状态或通过现有云端维护通道核验。不要以重启NapCat、重装机器人或清空数据来修复认证问题。

## 实现与安全

- 本机 [server.mjs](<F:/work/qq-deepseek-deploy/manager/server.mjs>) 只绑定127.0.0.1，固定Host、Origin、HttpOnly/SameSite会话与CSRF检查；前端无第三方CDN，数据库文本不作为HTML执行。
- [remote.py](<F:/work/qq-deepseek-deploy/manager/remote.py>) 是Python标准库独立管理程序。SSH每次核对它的SHA-256，拒绝本地/远端版本不一致；所有路径、容器名、命令白名单固定，不接受网页传入命令或文件路径。
- 读库不用插件构造器、不调用日评/发送函数。WAL读取在独立临时副本中进行，避免只读浏览改动正式SHM。
- 密钥和完整配置不进状态接口。登录授权、服务日志与请求传输临时文件保存在已核验私有权限的 `C:\Users\ASUS\.ssh\whale-manager-runtime`，新文件继承当前用户、SYSTEM和Administrators的访问权限；启动器与SSH桥接会检查权限，失败时拒绝运行。没有复制原SSH密钥，也没有手工修改任何已有文件权限。请求临时文件用完删除，页面请求不打印搜索词或聊天正文。工作区的旧启动授权已撤销；`.runtime/`仅保留无正文的验收元数据。
- 本机管理员及能以当前Windows用户读取文件的程序仍属于信任边界；不要把管理器反向代理到公网。
